# Памятка студента

Прочитайте один раз в начале семестра. Здесь всё, что от вас требуется.

## Что это за курс

36 часов, 18 занятий по одной паре в неделю, только практика.
Лекций нет — теория читается дома, конспекты в [docs/theory/](theory/).

Весь семестр вы делаете **один проект**: превращаете модель
из ноутбука в работающий ML-сервис с пайплайном, тестами, CI/CD
и мониторингом. В конце декабря — зачёт: защита этого проекта.

## Что нужно сделать до первого занятия

1. Пройти [docs/setup.md](setup.md) — поставить Python 3.11, Git, Docker.
2. Проверить окружение: `make check` должен напечатать `environment: OK`.
3. Прочитать [первый конспект](theory/01-what-is-mlops.md), 25 минут.
4. Прислать преподавателю ссылку на свой репозиторий в личные сообщения.

Если что-то не ставится — принесите **текст ошибки целиком**
на первое занятие. Не «не работает», а вывод терминала.

## Как устроена работа

### Персональный сид

При регистрации бот выдаёт вам число — персональный сид генерации данных.
Пропишите его в `params.yaml`:

```yaml
seed: 4271        # ваш, из /seed
```

У каждого студента свой сид, а значит свой датасет и свои метрики.
Работа с чужим сидом проверку не проходит.

После смены сида перегенерируйте данные: `make data`.

### Ваш репозиторий

Один репозиторий на весь семестр. Вы создаёте его из шаблона курса
на первом занятии и один раз присылаете ссылку преподавателю
в личные сообщения:

```
https://github.com/ваш-логин/ваш-репозиторий
```

Если репозиторий приватный — добавьте преподавателя в коллабораторы.

Дальше он растёт каждую неделю. К декабрю в нём будет пайплайн,
тесты, сервис, контейнер, CI/CD и мониторинг.

### Недельный цикл

| Когда | Что |
|---|---|
| До пары | прочитать конспект из `docs/theory/`, 20–30 минут |
| На паре | сделать основную работу по `lessons/NN-*/handout.md` |
| Дома | доделать домашнее задание, 1,5–2 часа |
| Перед пушем | сверить результат с разделом «Что сдать» в методичке |
| Итог недели | закоммитить и запушить в свой репозиторий |

### Как сдаётся работа

**Промежуточной сдачи нет.** После каждого занятия вы просто пушите
в свой репозиторий — ничего никуда отправлять не нужно.

Один раз в начале семестра пришлите преподавателю ссылку на свой
репозиторий в личные сообщения. Дальше он видит вашу работу там.

В конце семестра каждый **лично показывает весь проект** и отвечает
на вопросы. Это и есть зачёт.

Отсюда важное следствие: держите репозиторий в рабочем состоянии
постоянно. Сломанный `main` в ноябре — это риск не собрать проект
к декабрю.

**Раздел «Что сдать»** в конце каждой методички — те самые критерии,
по которым проект будут оценивать. Сверяйтесь с ним сами,
не дожидаясь замечаний.

```bash
python -m bot.checker --path . --lesson 5
```

## Правила проекта

Их пять, и они действуют с первого занятия.

1. **Никаких абсолютных путей.** `/Users/ваня/Desktop/данные.csv`
   не работает ни у кого, кроме вас.
2. **Никаких магических чисел в коде.** Всё, что подобрано, — в `params.yaml`.
3. **Данные и модели не коммитятся в Git.** С занятия 4 — в DVC.
4. **Секреты только через переменные окружения.** Токен, попавший
   в репозиторий, считается скомпрометированным и подлежит отзыву.
5. **Работа через ветки и Pull Request.** С занятия 2.

## Как оценивается

| Составляющая | Баллы |
|---|---|
| Работа на занятиях | 0–20 |
| Домашние задания (17 шт., по 2 балла) | 0–34 |
| Итоговый проект | 0–36 |
| Защита | 0–10 |

**Зачёт — от 60 баллов** при трёх обязательных условиях:

1. Проект набрал ≥ 20 из 36.
2. CI зелёный на момент защиты.
3. Сервис поднимается **одной командой на чужой машине**.

Третье условие — самая частая причина незачёта. Проект, который
работает только у автора, не считается работающим.

Полная рубрика — в [docs/assessment.md](assessment.md).

### Баллы за ДЗ

Ставит бот по доле пройденных проверок, преподаватель может изменить:

| Пройдено проверок | Балл |
|---|---|
| ≥ 90 % | 2 |
| 60–89 % | 1 |
| < 60 % | 0 |

Пересдавать можно неограниченно — в ведомость идёт лучший результат.
Просрочка больше двух недель: коэффициент 0,5.

## Про списывание

Скажем прямо, чтобы не было сюрпризов на защите.

Обсуждать задачи, помогать друг другу с отладкой и делать взаимное
ревью — можно и нужно, это часть курса. Сдавать чужую работу — нельзя.

Что проверяется автоматически:

* **персональный сид** — чужой репозиторий несёт чужие метрики;
* **история коммитов** — работа за семестр выглядит иначе, чем за ночь;
* **сходство кода** между репозиториями группы, с учётом переименования
  переменных и переписанных комментариев.

И главное: на защите вам зададут два вопроса **по конкретным строкам
вашего репозитория**. Объяснить чужой код под вопросы невозможно —
это и есть основная проверка.

## Курс сквозной — это важно

Занятие N опирается на результат занятия N−1. Пропустили неделю —
следующая пара пройдёт мимо вас.

Что делать, если отстали:

* методички самодостаточны, занятие можно пройти самостоятельно;
* занятия 3, 7 и 17 короткие, их вторая половина — приём долгов;
* **к занятию 10 обязательно должен быть работающий пайплайн DVC.**
  Без него сервис не собрать, и это точка невозврата.

## Главная проверка, которую делайте регулярно

В новой папке, не в рабочей копии:

```bash
git clone <ваш-репозиторий> /tmp/check && cd /tmp/check
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
dvc pull            # с занятия 4
pytest              # с занятия 8
```

Если что-то упало — вы что-то не закоммитили. Делайте эту проверку
раз в две недели, а не в декабре: в декабре чинить будет некогда.

## Чего от вас ждут

Не идеального кода и не лучшей метрики. Модель в курсе намеренно
простая — предмет изучения не она, а инженерия вокруг неё.

Ждут, что вы сможете объяснить любое решение в своём репозитории:
почему здесь `try/except`, почему такой порог, почему модель грузится
из реестра, а не из файла. На защите спросят именно это.

## Проблема

Репозиторий ML-проекта очень отличается от обычного приложения:
- **Модели весят гигабайты.** Git не рассчитан на бинарные файлы.
- **Данные меняются.** Если закоммитить датасет, репо станет тяжелым за день.
- **Секреты попадают в историю.** Удалили файл с токеном — он всё ещё в гите.
- **Хаос в истории.** Коммиты типа "fix", "работает", "не удалять" ничего не объясняют.

На занятии 1 вы ставили защиту через `.gitignore`. На этом занятии — защита от хаоса.

## Что нельзя коммитить в Git

### 1. Бинарные файлы (модели, данные)

**Почему.** Git хранит полную копию каждой версии.

```
Сценарий:
- День 1: вы закоммитили model.joblib (50 МБ)
- День 2: переобучили, закоммитили новую версию (50 МБ)
- День 7: обновили 7 раз

Итог:
- Репозиторий весит 350 МБ
- Клонирование длится минуты
- Размер никогда не уменьшится, даже если удалить файл
```

**Решение.** Файлы хранят в DVC (займятие 4) или S3, Git — только ссылка.

### 2. Секреты (токены, пароли, ключи)

**Почему.** Файл удаляется, но остаётся в истории Git.

```bash
# Даже если вы удалили .env, токен ещё в гите:
git log -p --all -S "sk-proj-" | head -20
```

**Правило:**
```
❌ НЕПРАВИЛЬНО: .env в репо
✅ ПРАВИЛЬНО: .env в .gitignore, в репо только .env.example
```

### 3. Файлы окружения

```
❌ __pycache__/
❌ .venv/
❌ .DS_Store
❌ *.pyc
```

Они автоматически генерируются, занимают место и отличаются на каждой машине.

## Pre-commit: защита от ошибок

`pre-commit` — это хуки, которые запускаются ДО коммита и не дают закоммитить мусор.

### Что устанавливать

```yaml
repos:
  # Базовые проверки
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v4.6.0
    hooks:
      - id: trailing-whitespace        # Пробелы в конце строк
      - id: end-of-file-fixer           # Пустая строка в конце файла
      - id: check-yaml                  # Синтаксис YAML
      - id: check-added-large-files     # Файлы больше 1 МБ
        args: [--maxkb=1000]
      - id: check-merge-conflict        # Неразрешённые конфликты
      - id: detect-private-key          # Приватные ключи

  # Форматирование кода
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.4.4
    hooks:
      - id: ruff                        # Линтер
        args: [--fix]
      - id: ruff-format                 # Форматер
```

### Установка

```bash
pip install pre-commit
pre-commit install
pre-commit run --all-files   # Первый прогон
git add .pre-commit-config.yaml
git commit -m "Добавить pre-commit"
```

**Важно:** первый прогон почти наверняка что-то исправит и выдаст ошибку.
Это нормально — хук исправил файлы, остановил коммит, чтобы вы посмотрели.

```bash
# Хук исправил файлы
git add -u
git commit -m "Исправить форматирование"
```

### Проверка: что хук блокирует

```bash
# Попытаемся закоммитить большой файл
make data && git add -f data/raw/churn.csv && git commit -m "проба"

# Результат: check-added-large-files блокирует коммит ✅
# Это ожидаемое поведение!

git reset   # Отменяем попытку
```

## Ветки и Pull Request

### Правило

**Работать в `main` напрямую запрещено!**

Все изменения идут через ветки и PR.

### Процесс

```bash
# 1. Создаём ветку
git switch -c feature/add-model-selection

# 2. Делаем правки
# ... редактируете файлы ...

# 3. Коммитим логически
git add -u
git commit -m "Добавить выбор модели через params.yaml"

# 4. Пушим ветку
git push -u origin feature/add-model-selection

# 5. На GitHub: создаём PR
```

### Как писать PR

Не просто описание, а ответы на три вопроса:

```markdown
## Что
Добавлен выбор алгоритма через params.yaml: logreg, random_forest, gradient_boosting.

## Зачем
Сравнение моделей требовало правки кода — это ломало воспроизводимость.
Теперь код не меняется, меняется только конфиг.

## Как проверить
Поменяйте train.model в params.yaml, запустите make train.
Метрики должны измениться, но код — нет.
```

### Как писать коммиты

**Правило:** один коммит = одно изменение.

❌ **Плохо:**
```
git commit -m "фикс"
git commit -m "работает"
git commit -m "правки после ревью"
```

✅ **Хорошо:**
```
git commit -m "Заполнить пропуски total_charges вместо dropna"
git commit -m "Добавить stratify в train_test_split"
git commit -m "Сохранять train_metrics.json после обучения"
```

**Принцип:** `git diff` уже показывает, ЧТО изменилось.
Коммит должен объяснить, ЗАЧЕМ.

## Code review в паре

### Процесс

1. **А создаёт PR** в своём репо
2. **Б ревьюит:** минимум один содержательный комментарий с привязкой к строке
3. **А правит** по замечаниям
4. **Б аппрувит,** А мержит

### Что считается содержательным комментарием

✅ **Хорошо:**
- "Здесь `0.2` — вынеси в `params.yaml`, иначе это значение дублируется в evaluate"
- "`except: pass` проглотит любую ошибку, включая опечатку в имени колонки"
- "Этот список признаков уже есть в `feature_columns()`, не дублируй"

❌ **Плохо:**
- "Мне не нравится"
- "Можно лучше?"
- "Ок"

### После аппрува

Выбираем **Squash and merge** (сплюсовать в один коммит) и удаляем ветку.

## Типичные ошибки и как их избежать

| Ошибка | Причина | Решение |
|--------|---------|---------|
| `pre-commit` переписал файлы, коммит "не прошёл" | это нормально, хук исправил | `git add -u && git commit` снова |
| В PR 40 файлов вместо 5 | закоммичены `__pycache__`, `.venv` | Проверить `.gitignore`, `git rm -r --cached` |
| `check-added-large-files` блокирует | пытаетесь закоммитить модель | Это защита! Используйте DVC |
| Конфликт в `params.yaml` | оба меняли один файл | Разберите вручную, коммитьте обе версии |
| Коммит прямо в `main` | привычка | Branch protection на GitHub + локально `git config core.protectNtfs true` |

## Git команды, которые пригодятся

| Команда | Зачем |
|---------|-------|
| `git switch -c имя` | создать ветку (новый синтаксис) |
| `git log --oneline --graph --all` | увидеть всё дерево веток |
| `git diff --staged` | что уйдёт в коммит |
| `git restore --staged файл` | убрать из индекса |
| `git revert ША` | отменить коммит, оставив историю |
| `git count-objects -vH` | размер репо |

⚠️ Training/Serving Skew

Сценарий:

Препроцессор в ноутбуке, но его забыли на сервере

❌ Production: ROC-AUC = 0.32 (ненормализованные данные!)

Почему?

# В ноутбуке: модель видит нормализованные данные X_scaled = StandardScaler().fit_transform(X_train) model.fit(X_scaled, y) # На сервере: забыли нормализацию! predictions = model.predict(X_raw) # модель ломается!
✅ Решение: Препроцессор + модель в одном Pipeline!

📈 Data Drift (история Сбербанка)

Ситуация:

2020 год - COVID. Все тарифы изменились, новые категории появились.

Месяц 1: ROC-AUC = 0.85 ✅ Месяц 2: ROC-AUC = 0.83 ✅ Месяц 3: ROC-AUC = 0.81 ⚠️ Месяц 4: ROC-AUC = 0.72 ❌ Месяц 5: ROC-AUC = 0.65 ❌❌

🔄 Reproducibility (Воспроизводимость)

Определение: Один и тот же код + одни и те же данные = одна и та же модель (всегда)

$ make train ROC-AUC: 0.785 $ make train (месяц спустя, на другой машине) ROC-AUC: 0.785 ← ОДИНАКОВО!

Почему это важно?

  • 🔬Можете экспериментировать (меняете параметр → запускаете снова)
  • 📈Можете доказать улучшение (не плацебо)
  • ⏮️Можете вернуться в прошлое (какие параметры были месяц назад?)
  • 👥Другие могут повторить результат

Как достичь:

✅ Зафиксировать seed: random_state=42
✅ Зафиксировать версии: requirements.txt
✅ Версионировать данные: dvc add data/
✅ Хранить параметры: params.yaml

👁️ Monitoring (Мониторинг)

Определение: Видеть что происходит с моделью в production (сейчас и историю)

Метрики сервиса:

Метрика Норма Проблема
RPS (запросы/сек) 125 req/s 0 req/s
Latency (p95) 42 ms 5000 ms
Error Rate 0.02% 50%

Метрики модели:

  • 📊ROC-AUC: была 0.85, стала 0.72 → ALARM!
  • 🌊Data Drift: данные изменились? (новые категории?)
  • 📉Model Drift: модель становится хуже?

Проблема:

Data Scientist Петр обучил модель. На его машине работает идеально. На production - не работает.

Почему?

❌ train, test = train_test_split(X, y, test_size=0.2) # каждый раз РАЗНЫЕ строки в тесте!
✅ train, test = train_test_split( X, y, test_size=0.2, random_state=params["seed"] ← зафиксировали! )
С MLOps: Проблема не возникла бы вообще, потому что random_state везде зафиксирован.
❓ Вопрос:

Где ещё могут быть незафиксированные random seeds?

🔧 Пример: Магические числа

История стартапа:

Нужно поменять threshold с 0.5 на 0.6

Без MLOps (2 часа поиска):

❌ if predictions > 0.5: # где это? в коде? ❌ THRESHOLD = 0.5 # может быть в constants? ❌ docker run ... -e THRESHOLD=0.5 # может в env? # БЕДА: threshold в трёх местах, в одном забыли менять!

С MLOps (10 секунд):

✅ params.yaml: evaluate: threshold: 0.5 ← один файл! # меняешь → всё работает
✅ Вывод: все параметры в одном месте = простота и надежность

# Как раздавать задания и проверять работы

Курс сквозной: один студент — один репозиторий на весь семестр,
17 домашних работ. При группе в 20 человек это 340 проверок.
Вручную столько не проверить, поэтому механика построена так,
чтобы преподаватель читал только то, что действительно требует человека.

## Принцип

Проверка разбита на три уровня, и каждый следующий включается только
если пройден предыдущий:

| Уровень | Кто проверяет | Что |
|---|---|---|
| 1 | GitHub Actions у студента | код запускается, тесты и линтер зелёные, пайплайн воспроизводится |
| 2 | [бот курса](../bot/) | структура проекта, содержимое файлов, история Git, статус CI |
| 3 | преподаватель | содержательное ревью: осмысленны ли решения |

Красный CI — работа не принимается, преподаватель её не открывает.
Не пройден чек-лист бота — студент видит конкретный список ❌ и дорабатывает сам.
До третьего уровня доходят только формально готовые работы, и на них
уходит 5 минут вместо получаса.

## Раздача заданий

### Вариант A: GitHub Classroom (рекомендуется)

Один раз перед семестром:

1. Опубликуйте [`template/`](../template/) как отдельный репозиторий
   и включите в его настройках **Template repository**.
2. Создайте организацию и классрум на [classroom.github.com](https://classroom.github.com).
3. Создайте **одно** задание на весь семестр — «Сквозной проект MLOps»,
   на основе вашего template-репозитория, individual, приватность на ваш выбор.
4. Раздайте ссылку-приглашение. Каждый студент получает свой репозиторий,
   вы автоматически в нём преподаватель.

Почему одно задание, а не 17: проект сквозной, ДЗ — это его этапы,
а не отдельные работы. Дробить на 17 репозиториев значит потерять историю.

Отдельные ДЗ фиксируются тегами (см. ниже), а не новыми репозиториями.

### Вариант B: без Classroom

1. Публикуете `template/` как template repository.
2. Студент жмёт **Use this template**, делает свой репозиторий.
3. Присылает ссылку боту: `/repo https://github.com/логин/репозиторий`.

Разницы для проверки нет: бот работает с любым URL.

### Вариант C: закрытый контур

Если GitHub недоступен — поднимите Gitea или GitLab CE в локальной сети.
Бот клонирует по любому git-URL; из проверок отвалятся только `gh_ci_green`
и `gh_release_exists` (они завязаны на GitHub API). Их можно убрать
из `bot/checks.yaml` или заменить на проверку файла, который пишет ваш CI.

### Выдача материалов занятия

Методички лежат в репозитории курса и раздаются ботом:
студент пишет `/task 5` и получает ссылку на `handout.md`
плюс список «что сдать» — тот самый, по которому его будут проверять.

Ничего рассылать вручную не нужно.

## Регламент сдачи

Работа принимается из ветки `main` репозитория студента.

```
/submit 5
```

Если нужно зафиксировать конкретное состояние (например, студент
уже ушёл вперёд, а сдаёт задним числом) — тег:

```bash
git tag hw-05 && git push origin hw-05
```
```
/submit 5 hw-05
```

Бот прогоняет чек-лист занятия, ставит авто-балл (2 / 1 / 0),
записывает результат и присылает вам уведомление.

Пересдавать можно сколько угодно — это не поблажка, а смысл:
студент доводит работу до зелёного сам, а не ждёт вашего комментария,
чтобы узнать, что забыл `.dockerignore`.

## Что делает преподаватель

**Раз в неделю, 10 минут:**

```
/report 5          — кто сдал, с каким результатом
/remind 5          — напомнить тем, кто не сдал
```

**По каждой сданной работе, 3–5 минут** — только содержательное:

* осмысленны ли решения или чек-лист пройден формально
  (тесты есть, но проверяют `assert not None`);
* обоснованы ли ответы на письменные вопросы ДЗ;
* адекватны ли комментарии в коде.

Оценка выставляется поверх автоматической:

```
/grade @ivanov 5 1 тесты формальные: test_model.py не ловит сдвиг таргета
```

Студент получает балл и комментарий в личку.

**Раз в семестр:**

```
/export            — ведомость в CSV для деканата
```

## Типовые сценарии

**Студент говорит «у меня всё работает, а бот не видит».**
Просите прислать вывод `python -m bot.checker --path . --lesson 5`
на его машине. В 9 случаях из 10 окажется, что он не закоммитил файл.
Это ровно тот урок, который курс и должен дать.

**Студент сдаёт в последнюю ночь и всё красное.**
Дедлайн ставится ботом (`/deadline 5 2026-10-14`), напоминание
уходит автоматически по `/remind`. Штраф за просрочку (×0,5
по `assessment.md`) выставляется вручную через `/grade`.

**Чек-лист оказался слишком строгим.**
Правите `bot/checks.yaml`, перезапускаете бота, делаете `/recheck 5` —
все сданные работы пересчитываются по новому чек-листу.
Балл может только вырасти: `/submit` пишет новую запись, а в ведомость
идёт лучшая.

**Нужно проверить кого-то прямо сейчас, без телеграма:**

```bash
python -m bot.checker --repo https://github.com/ivanov/mlops --lesson 9 --gh
```

## Как не дать списывать

Одного средства не существует — работает только слоями. Ни один слой
не ловит всё, но обойти четыре сразу дороже, чем сделать работу.

### Слой 1. Персональные данные (автоматически)

При регистрации бот выдаёт каждому студенту **персональный сид**
генерации данных — число от 1000 до 9999, детерминированное от его
Telegram ID. Студент прописывает его в `params.yaml`.

Следствие: у каждого свой датасет и **свои метрики**. Копия чужого
репозитория несёт чужой сид, и проверка `personal_seed` это ловит
на занятиях 1, 9 и 17 — не запуская код.

Это не останавливает того, кто скопировал код и перегенерировал данные
под себя. Зато отсекает самый частый случай — «клонировал и сдал».

### Слой 2. История коммитов (автоматически)

Работа, растянутая на семестр, устроена иначе, чем склонированная за ночь:

| Проверка | Занятие | Что ловит |
|---|---|---|
| `git_commit_days_min: 6` | 9 | всё сделано за один-два вечера |
| `git_commit_days_min: 12` | 17 | то же на масштабе семестра |
| `git_history_span_days: 60` | 17 | репозиторий создан в декабре |

Подделать историю можно, но это сознательный подлог, а не «взял у друга».

### Слой 3. Поиск заимствований (по команде)

```
/similar
```

Бот клонирует все репозитории группы и сравнивает попарно. Два момента,
которые делают это осмысленным:

**Файлы из шаблона исключены.** Все стартуют из одной заготовки,
и совпадение `src/config.py` ничего не значит. Сравнивается только то,
что студент дописал сам.

**Учитывается маскировка.** Считаются два отпечатка: лексический
(поток токенов без комментариев) и структурный (типы токенов вместо имён).
Переименование переменных и переписывание комментариев структурный
отпечаток не меняют — а это ровно то, что делают, когда прячут копипаст.

Отчёт показывает пары выше 80 % с разбивкой по файлам. Это **сигнал
посмотреть, а не приговор**: совпадать может и код, честно написанный
по одной методичке.

### Слой 4. Вопросы по строкам (на защите)

Последний и самый надёжный слой, автоматизации не поддаётся.

На защите открываете случайный файл в его репозитории и спрашиваете
«почему здесь так». Не общие вопросы про MLOps, а конкретные:

* «Покажите, где задаётся порог классификации. Почему такой?»
* «Что будет, если сюда придёт категория, которой не было при обучении?
  Покажите на живом сервисе.»
* «Уроните MLflow и сделайте запрос в `/predict`. Объясните, что видите.»
* «Какой ваш тест упадёт, если я сдвину таргет на строку? Покажите.»

Последние два — практические, просите выполнить прямо сейчас.
Написанный проект от скопированного это отличает надёжнее любой метрики.

### Чего делать не стоит

**Запрещать помогать друг другу.** Обсуждение и парное ревью —
часть занятия 2 и полезны. Ловить нужно сдачу чужой работы,
а не совместную отладку.

**Обвинять по одному сигналу.** Совпадение 85 % на одном файле —
повод спросить, а не поставить незачёт. Решение принимается после
разговора со студентом.

**Держать решение в открытом доступе.** См. следующий раздел.

## Эталонное решение и доступ к нему

`reference-project/` — это полный ответ на семестровый проект.
Пока он лежит в публичном репозитории курса, любой студент может
взять его целиком.

Варианты:

| Вариант | Плюс | Минус |
|---|---|---|
| Вынести в приватный репозиторий | студенты физически не достанут | нужен второй репозиторий, ссылки в гайдах меняются |
| Оставить публичным, ловить через `/similar` | эталон под рукой, ничего не менять | искушение прямое, а детекция работает постфактум |
| Публиковать после зачёта | и польза, и защита | эталон недоступен по ходу семестра как точка восстановления |

Рекомендация: **вынести в приватный репозиторий**. Соблазн взять готовое
решение по прямой ссылке слишком велик, а детектор заимствований
сработает уже после того, как студент потратил семестр впустую.

## Подготовка перед семестром: чек-лист

- [ ] `template/` опубликован как template repository
- [ ] Classroom настроен, ссылка-приглашение готова
- [ ] Бот запущен, `TEACHER_IDS` заполнен, `/roster` отвечает
- [ ] `GITHUB_TOKEN` выдан — иначе проверки CI не работают
- [ ] Дедлайны выставлены: `/deadline N ГГГГ-ММ-ДД` на все 17 занятий
- [ ] Решено, что делать с `reference-project/` (см. раздел выше)
- [ ] Студентам объявлено про персональные сиды и про `/similar`
- [ ] Проверено на себе: создайте тестовый репозиторий из шаблона,
      привяжите к боту, прогоните `/check 1` — увидите то же,
      что увидят студенты

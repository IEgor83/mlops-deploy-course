## 4. Обновление методичек (разослать сейчас)

Короткая версия для чата группы. Главное в ней — предупреждение
про `git pull`: без него часть студентов получит конфликт
прямо в решённых файлах.

> **Обновились методички занятий 4–17**
>
> В каждую добавлен новый раздел — требования, которых раньше
> в заданиях не было. Если занятие уже сдано, новый пункт доделаете
> вместе с ближайшим домашним заданием, отдельно пересдавать не нужно.
>
> Читать можно прямо на GitHub, скачивать необязательно:
> https://github.com/alsu124/mlops-deploy-course/tree/main/lessons
>
> **Если хотите обновить методички у себя локально — не делайте
> обычный `git pull`.** Он попробует слить ваши решённые файлы
> с заготовками из курса, и вы получите конфликт прямо в готовом коде.
> А если забрать из курса папку `docs/`, она затрёт ваши `runbook.md`,
> `model-card.md` и другие домашние работы.
>
> Безопасно — забрать только папку `lessons/`:
>
> ```
> # 1. Сначала сохраните свою работу
> git add -A
> git commit -m "Сохранить работу перед обновлением"
> git push
>
> # 2. Подключить репозиторий курса (один раз)
> git remote add upstream https://github.com/alsu124/mlops-deploy-course.git
> git fetch upstream
>
> # 3. Забрать ТОЛЬКО методички
> git checkout upstream/main -- lessons/
> git add lessons/
> git commit -m "Обновить методички из репозитория курса"
> git push
> ```
>
> Команда на шаге 3 меняет ровно одну папку. Ваш код, `docs/`,
> отчёты и история коммитов остаются нетронутыми.
>
> **Если у вас отдельный проект** (в репозитории нет папок `lessons/`
> и `template/`) — делать не нужно ничего, читайте методички на GitHub.
>
> **Так будет ещё не раз.** Методички я буду поправлять по ходу курса:
> где-то станет понятнее объяснение, где-то добавится требование.
> Каждый раз буду писать сюда, в чат. Ничего страшного в этом нет —
> обновление трогает только папку `lessons/`, ваш код и работы
> оно не затрагивает никогда.
>
> Подключить репозиторий курса (шаг 2) нужно **один раз**. Дальше
> обновление — три команды:
>
> ```
> git fetch upstream
> git checkout upstream/main -- lessons/
> git add lessons/ && git commit -m "Обновить методички" && git push
> ```
>
> Подробно, в том числе что делать, если включена защита ветки
> и `git push` отказывает:
> https://github.com/alsu124/mlops-deploy-course/blob/main/docs/UPDATE_FOR_STUDENTS.md

### Что ответить на частые вопросы

**«Я уже сдал занятие 5, мне переделывать?»**
Нет. Новый раздел доделывается вместе с ближайшим ДЗ.

**«У меня конфликт после обновления»**
Значит, была выполнена не та команда. `git reflog`, найти состояние
до обновления, `git reset --hard HEAD@{1}`. Ничего не потеряно,
пока есть история.

**«`git push` пишет `GH006: Protected branch update failed`»**
Сработала защита ветки с занятия 2 — так и должно быть.
Нужно через ветку и Pull Request, порядок команд в подробной инструкции.

**«Зачем вообще обновлять, если можно читать на GitHub?»**
Незачем. Локальная копия методичек — удобство, не требование.

## 5. Порядок сдачи (разослать сейчас)

> **Как сдаются работы — коротко**
>
> Промежуточной сдачи нет. После каждого занятия вы просто пушите
> работу в свой репозиторий. Ничего никуда отправлять не нужно:
> ни через бота, ни отдельным Pull Request.
>
> От вас нужно одно действие: **пришлите мне ссылку на свой
> репозиторий в личные сообщения**. Один раз. Дальше я вижу
> вашу работу там.
>
> Если репозиторий приватный — добавьте меня в коллабораторы.
>
> **В конце семестра каждый лично показывает весь проект** и отвечает
> на вопросы по своему коду. Это и есть зачёт. Оценивается проект
> целиком, а не отдельные лабы: они достраивают друг друга и по одной
> смысла не имеют.
>
> Отсюда важное: держите репозиторий в рабочем состоянии постоянно,
> а не приводите в порядок в декабре. Сломанный `main` в ноябре —
> это риск не собрать проект к защите.
>
> **Про Pull Request.** Для сдачи он не нужен. Но на занятии 2 вы
> делаете полный цикл ветка → PR → ревью напарника → мерж — это
> упражнение и требование к проекту, а не способ отправки работы.
>
> Подробно: https://github.com/alsu124/mlops-deploy-course/blob/main/HOW_TO_SUBMIT_LABS.md

### Что ответить на частые вопросы

**«А как вы узнаете, что я сдал?»**
По вашему репозиторию. Коммиты с датами видны, и история работы
входит в требования к проекту.

**«Я сделал лабу, надо что-то написать?»**
Нет. Запушили — и всё.

**«Репозиторий приватный, вы его увидите?»**
Только если добавите меня в коллабораторы. Сделайте это сразу.

**«Можно я буду работать через ветки и PR?»**
Можно и полезно. Просто это не способ сдачи, а ваша организация работы.

## 6. Перед зачётом (за две недели)

> До защиты осталось две недели. Проверьте себя **в новой папке**,
> не в рабочей копии:
>
> ```
> git clone <ваш-репозиторий> /tmp/check && cd /tmp/check
> dvc pull
> docker compose -f docker/docker-compose.yml up -d
> curl -s localhost:8000/health
> pytest -q
> ```
>
> Упала хотя бы одна команда — вы не готовы. Самая частая причина
> незачёта: проект работает только на машине автора.
>
> Также обязательно: зелёный CI на последнем коммите main
> и опубликованный образ.
>
> Скачайте заранее docker-образы и зависимости — интернет в аудитории
> может не работать, и это не будет уважительной причиной.
>
> Последний коммит принимается за сутки до защиты.
> Регламент защиты: https://github.com/alsu124/mlops-deploy-course/blob/main/docs/assessment.md

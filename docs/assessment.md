# Зачёт: требования, критерии, процедура

Форма контроля — **зачёт** (недифференцированный) на занятии 18.
Зачёт ставится за защищённый сквозной проект, а не за ответ по билету.
Билеты с вопросами используются только на пересдаче и для добора баллов.

## Итоговая формула

| Составляющая | Баллы | Что учитывается |
|---|---|---|
| Работа на занятиях | 0–20 | наличие результата занятия в репозитории к следующей паре |
| Домашние задания (17 шт.) | 0–34 | по 2 балла: 2 — принято, 1 — принято с замечаниями, 0 — не сдано |
| Итоговый проект | 0–36 | по рубрике ниже |
| Защита (демо + вопросы) | 0–10 | владение своим проектом |
| **Итого** | **0–100** | |

**Зачёт — от 60 баллов**, при обязательных условиях:

1. Итоговый проект набрал ≥ 20 из 36.
2. CI в репозитории зелёный на момент защиты.
3. Сервис поднимается одной командой на машине преподавателя.

Первые два условия проверяются автоматически, третье — на защите.
Невыполнение любого из них означает «не зачтено» независимо от суммы баллов.

## Требования к итоговому проекту

Проект — это личный Git-репозиторий студента, выросший из шаблона курса.
Обязательный состав:

### 1. Репозиторий и код (6 баллов)

- [ ] Структура: `src/`, `tests/`, `docker/`, `.github/workflows/`, конфиги в корне
- [ ] `README.md`: задача, архитектура, инструкция запуска, скриншот дашборда
- [ ] `pre-commit` настроен, `ruff` проходит без ошибок
- [ ] Секретов в истории нет (`.env` в `.gitignore`, токены через переменные окружения)
- [ ] История коммитов осмысленная: ≥ 15 коммитов, работа шла через ветки и PR

### 2. Данные и воспроизводимость (6 баллов)

- [ ] Данные под DVC, remote настроен, `dvc pull` работает с чистого клона
- [ ] `dvc.yaml` описывает пайплайн prepare → train → evaluate
- [ ] `dvc repro` на чистой машине воспроизводит метрики с точностью до 3-го знака
- [ ] Гиперпараметры вынесены в `params.yaml`, в коде нет магических чисел

### 3. Эксперименты (5 баллов)

- [ ] В MLflow ≥ 10 прогонов с разными параметрами
- [ ] Логируются: параметры, метрики, артефакты (модель, отчёт, графики)
- [ ] Лучшая модель зарегистрирована в Model Registry, стадия `Production`
- [ ] В README обосновано, почему выбрана именно эта модель

### 4. Тесты и CI (6 баллов)

- [ ] ≥ 8 тестов: данные, фичи, модель, API
- [ ] Есть тест на схему входных данных и тест на инвариант поведения модели
- [ ] CI прогоняет lint + tests на каждый PR, ветка `main` защищена
- [ ] CD собирает и публикует Docker-образ по тегу

### 5. Сервис и контейнер (7 баллов)

- [ ] FastAPI: `/health`, `/predict`, `/predict/batch`, `/metrics`
- [ ] Валидация входа Pydantic; на некорректный вход — 422 с понятным сообщением
- [ ] В ответе возвращается версия модели
- [ ] Dockerfile multi-stage, запуск от non-root, образ < 500 МБ
- [ ] `docker compose up` поднимает api + mlflow + minio и стенд работает

### 6. Мониторинг (6 баллов)

- [ ] Prometheus собирает метрики сервиса, дашборд Grafana сохранён в репозитории
- [ ] Настроен ≥ 1 осмысленный алерт (например, p95 latency > 500 мс)
- [ ] Evidently-отчёт по дрейфу данных приложен, дрейф на подготовленном срезе обнаружен
- [ ] Описан регламент: что делает дежурный, когда алерт сработал

Итого 36 баллов. Занятие 16 (Prefect / автопереобучение) — **необязательная часть**:
рабочий flow переобучения даёт +4 бонусных балла сверх суммы.

## Процедура защиты

12 минут на человека:

1. **Демо (7 мин).** Ноутбук студента, проектор. Живой прогон, не слайды:
   клонируем чистую копию → `docker compose up` → запрос в сервис → показ MLflow →
   показ дашборда → показ отчёта о дрейфе.
2. **Вопросы (5 мин).** Два вопроса по своему проекту + один из списка ниже.

Слайды не требуются. Презентация вместо живого запуска — минус 5 баллов защиты.

## Чек-лист студента перед защитой

Прогоните на **чистой** машине или в новой папке:

```bash
git clone <ваш-репозиторий> check && cd check
dvc pull
docker compose up -d
curl -s localhost:8000/health
curl -s -X POST localhost:8000/predict -H 'Content-Type: application/json' -d @examples/request.json
pytest -q
docker compose down -v
```

Если хоть одна команда упала — вы не готовы. Самая частая причина незачёта:
проект работает только на машине автора, потому что путь/секрет/данные зашиты локально.

## Вопросы к зачёту

Используются на защите (по одному) и на пересдаче (по три).

**Воспроизводимость и данные**
1. Что именно делает `dvc add` с файлом и что попадает в Git?
2. Чем `dvc repro` отличается от простого перезапуска скрипта? Как DVC понимает, что стадию можно пропустить?
3. Почему модель нельзя хранить в Git? Что хранить вместо неё?
4. Что такое детерминизм обучения и какие источники недетерминизма вы знаете?

**Эксперименты**
5. Что такое run, experiment и artifact в MLflow?
6. Зачем нужен Model Registry, если модель уже лежит в артефактах прогона?
7. Как в вашем проекте сервис узнаёт, какую версию модели загружать?

**Тестирование и CI**
8. Чем тестирование ML-системы отличается от тестирования обычного бэкенда?
9. Что такое поведенческий тест модели? Приведите пример из вашего проекта.
10. Что должно происходить в CI на каждый PR и почему именно это?

**Сервис и контейнеры**
11. Зачем нужен multi-stage Dockerfile? Что вы вынесли в первую стадию?
12. Почему процесс в контейнере не должен работать от root?
13. Чем `/health` отличается от `/ready` и зачем это разделение?
14. Как отдать предсказание для 10 000 объектов, не положив сервис?

**Эксплуатация**
15. Что такое data drift, concept drift и чем они различаются на практике?
16. Какие метрики сервиса вы мониторите и какой алерт настроили? Почему такой порог?
17. Метрики модели упали. Опишите порядок действий.
18. Опишите цикл автоматического переобучения в вашем проекте.

## Долги и догон

Курс сквозной: пропуск занятия ломает следующее. Правила:

- Пропущенное занятие закрывается **методичкой самостоятельно** — они самодостаточны.
- Просроченное ДЗ принимается со штрафом ×0,5 в течение двух недель, дальше — 0 баллов.
- Занятия 3, 7, 17 короткие: их вторая половина отведена под приём долгов.
- Если к занятию 10 нет работающего пайплайна DVC — это стоп-сигнал: без него
  не собрать сервис. Такому студенту выдаётся эталонное состояние из
  эталонное состояние из приватного репозитория преподавателя как точка старта,
но с потерей баллов за блок 1.

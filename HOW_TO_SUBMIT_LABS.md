# Как выполнять лабораторные и как они сдаются

## Главное про сдачу

**Промежуточной сдачи нет.** Вы не отправляете работы после каждого
занятия — ни через бота, ни отдельным Pull Request.

Всё, что вы делаете, копится в вашем репозитории на GitHub.
В конце семестра вы **лично показываете весь проект** и отвечаете
на вопросы. Это и есть зачёт.

От вас нужно ровно два действия:

1. **Один раз** прислать преподавателю ссылку на свой репозиторий —
   в личные сообщения.
2. **Регулярно пушить** свою работу туда. Не раз в семестр, а по ходу:
   история коммитов показывает, что работа шла, и она входит
   в требования к проекту.

Всё. Больше ничего отправлять не нужно.

---

## Почему так

Проект сквозной: каждое занятие достраивает предыдущее. Отдельно
сдавать занятие 5 бессмысленно — оно живёт только вместе с 1–4.
Оценивается целое, и оценивается вживую: вы показываете, как проект
работает, и объясняете свои решения.

Отсюда следствие, которое стоит принять всерьёз: **репозиторий нужно
держать в рабочем состоянии постоянно**, а не приводить в порядок
в декабре. Сломанный `main` в ноябре — это не «потом починю»,
это риск не собрать проект к защите.

## Как начать

### Шаг 1. Создайте свой репозиторий на GitHub

Название на ваше усмотрение, например `mlops-ФАМИЛИЯ`.
Репозиторий может быть публичным или приватным — если приватный,
добавьте преподавателя в коллабораторы.

### Шаг 2. Возьмите шаблон проекта

Вам нужна папка `template/` из репозитория курса — это заготовка
вашего проекта.

```bash
git clone https://github.com/alsu124/mlops-deploy-course.git /tmp/course
cp -r /tmp/course/template ~/mlops-ФАМИЛИЯ
cd ~/mlops-ФАМИЛИЯ
```

### Шаг 3. Свяжите со своим репозиторием

```bash
git init -b main
git add .
git commit -m "Создать проект из шаблона курса"
git remote add origin https://github.com/ВАШ_НИК/mlops-ФАМИЛИЯ.git
git push -u origin main
```

### Шаг 4. Пришлите ссылку преподавателю

В личные сообщения, один раз:

```
https://github.com/ВАШ_НИК/mlops-ФАМИЛИЯ
```

## Как устроена работа над лабой

1. Откройте `lessons/NN-*/handout.md` в репозитории курса
   (или на GitHub — скачивать необязательно).
2. Выполните шаги.
3. Сверьтесь с разделом **«Что сдать»** в конце методички —
   это и есть критерии, по которым проект будут оценивать.
4. Закоммитьте и запушьте.

```bash
git add -A
git commit -m "Занятие 4: данные под DVC, паспорт датасета"
git push
```

**Сообщения коммитов имеют значение.** По ним видно, что происходило
в проекте, и они входят в требования (занятие 2). `фикс`, `работает`,
`правки` — плохо. «Заполнять пропуски total_charges вместо dropna» — хорошо.

## Про Pull Request

Отдельный PR для сдачи создавать **не нужно**.

Но сам навык остаётся в программе: на занятии 2 вы делаете полный цикл
ветка → PR → ревью напарника → мерж, и один смерженный PR входит
в требования к проекту. Разница простая:

| | Зачем |
|---|---|
| PR на занятии 2 | учебное упражнение и требование к проекту |
| PR как способ сдачи | **не используется** |

Работать через ветки и PR дальше — ваше право и хорошая привычка,
но обязательным способом отправки работы это не является.

## Что должно быть в репозитории к концу

Полный список — в [docs/assessment.md](docs/assessment.md).
Коротко: воспроизводимый пайплайн, трекинг экспериментов, тесты, CI/CD,
сервис в контейнере, мониторинг и документация.

Главная проверка, которую стоит делать раз в пару недель,
**в новой папке**, а не в рабочей:

```bash
git clone <ваш-репозиторий> /tmp/check && cd /tmp/check
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
make data && make prepare && make train
```

Если упало — вы что-то не закоммитили. Лучше узнать это в октябре,
чем в декабре.

## Как проходит зачёт

Каждый по очереди, со своего ноутбука:

* показываете, как проект запускается и работает;
* отвечаете на вопросы по своему коду — по конкретным строкам
  в вашем репозитории;
* отвечаете на один вопрос из общего списка.

Регламент, критерии и список вопросов — в [docs/assessment.md](docs/assessment.md).

Готовьтесь к тому, что спросят «почему здесь сделано именно так».
Это и есть основная проверка: объяснить чужой код невозможно.

## Частые вопросы

**Нужно ли что-то отправлять после каждого занятия?**
Нет. Только пушить в свой репозиторий.

**Нужен ли бот?**
Нет, бот не используется.

**Нужно ли делать Pull Request для сдачи?**
Нет. PR делается один раз на занятии 2 как упражнение.

**Мой репозиторий приватный, это нормально?**
Да, добавьте преподавателя в коллабораторы.

**Я отстал на две недели, что делать?**
Методички самодостаточны, занятие проходится самостоятельно.
Если не получается — пишите преподавателю, не копите.

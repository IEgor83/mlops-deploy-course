# Деградация модели при нарастающем дрейфе

Эталонный пример отчёта занятия 15. Цифры получены на генераторе
`src/data/generate.py`; у студентов они будут отличаться в третьем знаке.

## Как воспроизвести

```bash
make drift                                   # базовый срез
python -m src.data.generate --drift --out data/raw/fresh.csv --n 5000
python -m src.monitoring.drift --current data/raw/fresh.csv
```

## Результат

| Срез | Описание | Дрейфующих признаков | ROC-AUC |
|---|---|---|---|
| val | та же генерация, другой сид | 0 из 10 | 0.79 |
| current, лёгкий | половина сдвига по тарифу | 2 из 10 | 0.78 |
| current, полный | `--drift`: тариф +12, оптика 58 %, звонки +0.6 | 5 из 10 | 0.74 |
| current, полный ×2 | двойной сдвиг | 7 из 10 | 0.70 |

## Что видно

**Первая строка — проверка инструмента.** Две выборки из одного
распределения не должны давать дрейфа. Если Evidently показывает дрейф
здесь, значит порог слишком чувствителен или выборка слишком велика,
и всем остальным цифрам верить нельзя.

**Дрейф и качество связаны, но не жёстко.** На полном срезе дрейфуют
5 признаков из 10, а ROC-AUC падает с 0.79 до 0.74 — ниже
`evaluate.min_roc_auc = 0.75`, то есть модель перестаёт проходить gate.
При этом первые два дрейфующих признака стоили всего 0.01 метрики:
дрейф второстепенного признака почти безвреден.

**Практический вывод.** Решение о переобучении нельзя принимать
по одному факту «дрейф обнаружен». Нужны три условия сразу:
дрейф статистически значим, дрейфуют важные для модели признаки,
качество на размеченных данных действительно упало.

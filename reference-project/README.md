# Churn MLOps — эталонное решение курса

![CI](https://github.com/alsu124/mlops-deploy-course/actions/workflows/ci.yml/badge.svg)

Это **ответ преподавателя**: состояние, к которому студент приходит к занятию 17.
Студенты работают не здесь, а в своём репозитории, выросшем из [`../template`](../template).

Проект используйте как:
* точку восстановления, если студент безнадёжно сломал свой репозиторий;
* образец при проверке ДЗ;
* стенд для проверки аудитории перед семестром (`make all` должен пройти).

## Задача

Предсказание оттока клиентов телеком-оператора: бинарная классификация
на табличных данных, 10 признаков, целевая метрика — ROC-AUC.
Данные генерируются скриптом с фиксированным сидом (`src/data/generate.py`),
поэтому пайплайн воспроизводится офлайн, а флаг `--drift` даёт срез
«следующего квартала» для занятия про мониторинг.

## Архитектура

```
              ┌────────────┐   models:/churn-classifier/Production
              │  MLflow    │◄──────────────────────────────┐
              │  :5000     │                               │
              └─────┬──────┘                               │
       артефакты    │  метаданные                    ┌─────┴──────┐
   ┌────────────────▼───┐  ┌──────────────┐          │    api     │
   │  MinIO :9000       │  │ Postgres     │          │   :8000    │
   └────────────────────┘  └──────────────┘          └─────┬──────┘
                                                            │ /metrics
   dvc repro:  generate → prepare → train → evaluate   ┌────▼───────┐
                                                       │ Prometheus │──► Grafana
                                                       │   :9090    │     :3000
                                                       └────────────┘
```

Обучение и инференс разведены: `dvc repro` порождает модель и кладёт её
в реестр, сервис только читает оттуда и никогда не обучает.

## Быстрый старт

```bash
python -m venv .venv && source .venv/bin/activate
make install
make all          # generate -> prepare -> train -> evaluate -> tests -> lint
make serve        # http://localhost:8000/docs
```

Готовый образ, без сборки:

```bash
docker run -p 8000:8000 ghcr.io/alsu124/mlops-deploy-course:1.0.0
```

Полный стенд с MLflow, MinIO, Prometheus и Grafana:

```bash
make up
# api        http://localhost:8000/docs
# mlflow     http://localhost:5000
# minio      http://localhost:9001   (minioadmin / minioadmin)
# prometheus http://localhost:9090
# grafana    http://localhost:3000   (admin / admin)
make down
```

## Что где лежит

```
src/
  config.py            загрузка params.yaml, разрешение путей — единственный источник настроек
  logging_setup.py     единый формат логов для всех точек входа
  data/generate.py     генератор сырых данных, --drift для занятия 15
  data/prepare.py      очистка + детерминированный сплит train/val/test
  features.py          ColumnTransformer: препроцессинг едет в прод вместе с моделью
  train.py             обучение + логирование в MLflow (--no-mlflow для CI)
  evaluate.py          оценка на тесте + gate качества (падает, если ROC-AUC < порога)
  monitoring/drift.py  отчёт Evidently: HTML для человека, JSON для автоматики
  flows/retrain.py     Prefect-flow «дрейф -> переобучение -> промоут -> /reload»
  service/             FastAPI: схемы, загрузчик модели, эндпоинты и метрики
tests/                 30 тестов: данные, фичи, поведение модели, HTTP-контракт
docker/                Dockerfile (multi-stage) и compose-стенд
monitoring/            конфиг Prometheus, правила алертов, дашборд Grafana
.github/workflows/     CI (lint + tests + repro) и CD (сборка и публикация образа)
```

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | жив ли процесс, загружена ли модель, её версия |
| POST | `/predict` | предсказание для одного клиента |
| POST | `/predict/batch` | до 1000 клиентов за запрос |
| POST | `/reload` | подтянуть новую версию модели без рестарта |
| GET | `/metrics` | метрики для Prometheus |
| GET | `/docs` | интерактивная документация |

Некорректный вход — 422 с указанием поля. Модель не загружена — 503.
В каждом ответе возвращается `model_version`: потребитель должен
различать «обновился сервис» и «обновилась модель».

Примеры запросов — в [`examples/`](examples/).

## Мониторинг

Собираются четыре сигнала сервиса (latency, traffic, errors, saturation)
плюс пятый, специфичный для ML: гистограмма `prediction_probability` —
сдвиг распределения предсказаний виден за часы, а падение бизнес-метрик
за недели.

* конфиг Prometheus и правила алертов — [`monitoring/`](monitoring/)
* дашборд Grafana — [`monitoring/grafana/dashboards/`](monitoring/grafana/dashboards/)
* что делает дежурный по каждому алерту — [`docs/runbook.md`](docs/runbook.md)
* отчёт о дрейфе и деградации — [`reports/DRIFT.md`](reports/DRIFT.md)

## Замечания для преподавателя

**F1 низкий — это специально.** На тестовой выборке ROC-AUC ≈ 0.79, а F1 при
пороге 0.5 ≈ 0.39: классы несбалансированы (доля оттока ≈ 0.21). Это хороший
повод на занятии 6 обсудить, почему порог — это продуктовое решение, а не
константа из туториала, и предложить подобрать его по PR-кривой.

**Пайплайн работает и без Docker.** `make all` не требует ни одного контейнера —
занятия 1–9 полностью проходимы на машине без прав администратора.

**Версия Evidently зафиксирована жёстко** (`evidently==0.4.40`): API менялся между
минорными релизами, и «просто обновить» посреди семестра означает переписать
`src/monitoring/drift.py` и методичку занятия 15.

**Порог качества в `params.yaml`** (`evaluate.min_roc_auc: 0.75`) — это тот самый
gate, из-за которого CI краснеет при деградации модели. Показывайте его студентам
специально: многие впервые видят, что тест может падать по метрике.

## Расхождения с автоматическим чек-листом

`python -m bot.checker --path reference-project --lesson N` покажет
несколько непройденных пунктов. Это ожидаемо: часть состояния
машинозависима и не может лежать в репозитории курса.

| Не проходит | Почему | Появится после |
|---|---|---|
| `.dvc/config`, `dvc.lock` | remote указывает на локальный путь или на ваш MinIO | `dvc init && dvc repro` на вашей машине |
| `reports/drift.html` | генерируется Evidently на реальном прогоне | `make drift` |
| Статус CI, наличие релиза | эталон живёт внутри репозитория курса, у него нет своего CI | публикации как отдельного репозитория |
| Минимум коммитов | у эталона нет истории из 15+ коммитов за семестр | — |

У студента все эти пункты обязаны проходить: это и есть разница между
«код написан» и «проект работает».

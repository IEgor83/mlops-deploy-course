# Занятие 12. Локальный прод-стенд — план

**Цель:** пять сервисов поднимаются одной командой и видят друг друга;
студент понимает сети, зависимости и healthcheck.

**Артефакт:** `docker/docker-compose.yml`, `docker compose up` поднимает
api + mlflow + minio + postgres, сервис грузит модель из Registry.

## Тайминг

| Мин | Что |
|---|---|
| 0–10 | Проверка ДЗ: таблица размеров образа |
| 10–25 | Демо: ручной запуск пяти контейнеров |
| 25–75 | Работа |
| 75–85 | Разбор сетевых ошибок |
| 85–90 | ДЗ |

## Демо (10–25 мин)

Начните с боли — запустите стенд руками, вслух:

```bash
docker network create mlops
docker run -d --network mlops --name postgres -e POSTGRES_PASSWORD=... postgres:16
docker run -d --network mlops --name minio -e MINIO_ROOT_USER=... minio/minio server /data
# ... и так далее, пять команд с флагами
```

К третьей команде группа уже поняла. Спросите: «Как передать это коллеге?
Как воспроизвести завтра? Что если postgres не успел стартовать?»

Затем `docker compose up -d` — и всё то же самое из одного файла.

## Что объяснить обязательно

**DNS внутри compose.** Сервисы обращаются друг к другу **по имени сервиса**,
не по localhost. Из контейнера `api` MLflow доступен как `http://mlflow:5000`.
`localhost` внутри контейнера — это сам контейнер.

Это ошибка номер один на занятии. Нарисуйте на доске: хост, внутри него
сеть compose, в ней пять контейнеров. Порты в `ports:` — это дырки
из хоста внутрь, они нужны только вам, не сервисам между собой.

**`depends_on` без `condition` почти бесполезен.** Он ждёт запуска контейнера,
а не готовности сервиса. Postgres стартует за 3 секунды, а принимать
соединения начинает через 8. Отсюда `condition: service_healthy` + `healthcheck`.

**Профили для слабых машин.** Полный стенд требует ~3 ГБ RAM.
Если в аудитории машины на 4 ГБ — показать `--profile lite`.

## Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `Connection refused` к mlflow из api | указан `localhost:5000` | Только `http://mlflow:5000` |
| MLflow падает при старте | postgres ещё не готов | `condition: service_healthy` |
| `port is already allocated` | 5000 занят (на macOS — AirPlay) | Сменить порт на хосте: `5001:5000` |
| Данные пропали после `down` | `down -v` удаляет тома | Объяснить разницу `down` и `down -v` |
| MinIO: бакет не найден | никто его не создал | Сервис-инициализатор или создать руками в консоли |
| Всё виснет, машина не тянет | 5 контейнеров на 4 ГБ | `--profile lite` |

## Про порт 5000 на macOS

Отдельно предупредите: в macOS порт 5000 занят AirPlay Receiver.
Либо выключить в системных настройках, либо пробрасывать `5001:5000`.
Это съедает 15 минут у половины владельцев маков, если не сказать заранее.

## Ключевая мысль

> `docker compose up` — это исполняемая документация по развёртыванию.
> Она не устаревает, потому что ей пользуются.

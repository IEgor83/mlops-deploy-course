# Занятие 9. CI на GitHub Actions — план

**Цель:** проверки, которые студент до сих пор запускал руками, выполняются
автоматически на каждый PR; красный CI блокирует мерж.

**Артефакт:** зелёный workflow, защита `main` с обязательной проверкой,
бейдж в README.

## Тайминг

| Мин | Что |
|---|---|
| 0–10 | Проверка ДЗ: покрытие тестами |
| 10–25 | Демо: почему «у меня локально работает» |
| 25–75 | Работа |
| 75–85 | Разбор падений CI |
| 85–90 | ДЗ |

## Демо (10–25 мин)

Заготовьте PR, в котором тесты падают, а автор написал «у меня всё зелёное».
Причина: в его рабочей копии лежат данные, сгенерированные ещё в сентябре,
а `.gitignore` их не пускает в репозиторий.

Покажите на проекторе:

```bash
git clone <репо> /tmp/ci-demo && cd /tmp/ci-demo
pip install -r requirements.txt
pytest
```

Падает. Вот что видит CI: **чистую машину без вашей истории**.

Главная мысль: CI ценен не тем, что «запускает тесты», а тем, что делает
это в окружении, где нет ничего лишнего. Это единственная объективная
проверка утверждения «проект работает».

## Структура workflow — на доску

Два независимых job, а не один длинный:

* `quality` — линтер и тесты, ~2 минуты;
* `pipeline` — воспроизведение `dvc repro` на маленькой выборке, ~4 минуты.

Зачем разделять: по красному чек-боксу сразу видно, что сломалось —
код или пайплайн. В одном job пришлось бы читать лог.

## Что объяснить обязательно

**Данные в CI.** У раннера нет доступа к вашему MinIO на localhost.
Два честных пути:
1. генерировать маленький датасет прямо в CI (учебный вариант, используем его);
2. `dvc pull` из облачного хранилища с ключами из GitHub Secrets
   (промышленный вариант, показать как устроено).

**Секреты.** Покажите Settings → Secrets and variables → Actions.
Подчеркните: секрет, попавший в лог CI, скомпрометирован —
GitHub маскирует значения секретов, но только если они пришли из Secrets.

**Кэш.** `cache: pip` в `setup-python` экономит полторы минуты на прогон.
При 20 студентах × 10 прогонов в неделю это заметно.

## Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `No module named src` | нет `__init__.py` или запуск из другой папки | Проверить структуру, запускать `python -m` |
| CI зелёный, но ничего не проверял | опечатка в `on:` или в путях | Открыть вкладку Actions, посмотреть, что реально выполнилось |
| Пайплайн в CI идёт 12 минут | обучение на полном датасете | `--n 4000`, объяснить: в CI проверяем живость, не качество |
| `dvc pull` падает в CI | нет ключей | Либо Secrets, либо генерация данных |
| Workflow не запускается | файл не в `.github/workflows/` | Путь должен быть точным |

## Ключевая мысль

> «У меня локально работает» — это не утверждение о проекте,
> это утверждение о вашей машине.

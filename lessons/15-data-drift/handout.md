## Проблема

Ваш проект защищён со всех сторон: тесты, CI, quality gate, алерты,
дашборд. Всё зелёное.

Через три месяца бизнес говорит: «модель работает хуже, чем весной».
Вы проверяете — код не менялся, тесты проходят, latency в норме,
ошибок нет. Что произошло?

Изменились не вы, а мир: оператор поднял цены, конкурент запустил акцию,
доля оптики выросла. Модель учили на прошлом распределении, а приходит новое.

## Шаг 2. Три вида дрейфа

| Вид | Что меняется | В нашем случае | Когда заметен |
|---|---|---|---|
| Data drift | распределение признаков | тариф подорожал, больше оптики | сразу, метки не нужны |
| Target drift | распределение таргета | отток вырос с 21 % до 30 % | когда пришли метки |
| Concept drift | связь признаков и таргета | дорогой тариф больше не ведёт к уходу | позже всего |

Практический вывод: data drift — единственное, что можно измерить
немедленно. Настоящие метки оттока приходят через месяцы, и ждать их,
чтобы узнать о проблеме, нельзя.

```python
def build_report(reference: pd.DataFrame, current: pd.DataFrame, columns: list):
    from evidently.metric_preset import DataDriftPreset, TargetDriftPreset
    from evidently.report import Report

    presets = [DataDriftPreset()]
    if TARGET in reference.columns and TARGET in current.columns:
        presets.append(TargetDriftPreset())

    keep = [c for c in columns + [TARGET] if c in reference.columns and c in current.columns]
    report = Report(metrics=presets)
    report.run(reference_data=reference[keep], current_data=current[keep])
    return report
```

**Reference — это данные обучения**, а не «прошлая неделя».
Модель училась на них, и именно с ними нужно сравнивать всё,
что приходит потом.

## Шаг 4. Два формата вывода

Отчёт нужен в двух видах — и это принципиально:

```python
report.save_html("reports/drift.html")     # для человека: посмотреть, разобраться

summary = summarize(report)                 # для автоматики: принять решение
json.dump(summary, open("reports/drift.json", "w"), indent=2)
```

```python
def summarize(report) -> dict:
    """Достаём из отчёта то немногое, по чему принимается решение."""
    payload = report.as_dict()
    result = payload["metrics"][0]["result"]
    by_column = result.get("drift_by_columns", {})
    return {
        "dataset_drift": bool(result.get("dataset_drift", False)),
        "share_of_drifted_columns": float(result.get("share_of_drifted_columns", 0.0)),
        "n_drifted_columns": int(result.get("number_of_drifted_columns", 0)),
        "drifted_columns": sorted(n for n, i in by_column.items() if i.get("drift_detected")),
    }
```

HTML читает человек раз в неделю. JSON читает пайплайн переобучения
каждую ночь — это вы соберёте на занятии 16.

## Шаг 6. Дрейф ≠ проблема

Важный момент, который отличает понимание от применения инструмента.

Проверьте: если сравнить train с val (обе выборки из одного распределения),
Evidently дрейфа не покажет. Если взять выборку в миллион строк,
статистический тест найдёт значимое различие практически везде —
при огромной выборке значимым становится ничтожное различие.

Поэтому решение принимается по трём признакам вместе:

1. дрейф статистически обнаружен;
2. дрейфуют **важные** для модели признаки (не те, что она почти не использует);
3. **качество действительно упало** — если есть метки.

Пункт 3 главный. Дрейф — это сигнал посмотреть, а не команда переобучать.

# Занятие 15. Мониторинг данных и модели — план

**Цель:** студент понимает, что модель деградирует без изменения кода,
и умеет это обнаруживать.

**Артефакт:** отчёт Evidently с зафиксированным дрейфом, JSON для автоматики,
измеренная деградация метрики на дрейфовых данных.

## Тайминг

| Мин | Что |
|---|---|
| 0–10 | Проверка ДЗ: runbook, алерт на ошибки |
| 10–25 | Демо: модель, которая испортилась сама |

## Демо (10–25 мин)

Самая наглядная демонстрация второй половины курса.

```bash
# модель, обученная на исходных данных
python -m src.evaluate                  # ROC-AUC ~0.79

# данные "следующего квартала"
python -m src.data.generate --drift --out data/raw/fresh.csv --n 5000
```

Прогоните ту же модель на дрейфовых данных и покажите падение метрики.
Ключевая фраза:

> Код не менялся. Тесты зелёные. CI зелёный. Модель стала хуже.
> Ни один инструмент из первых четырнадцати занятий этого не заметил.

## Три вида дрейфа — на доску

| Вид | Что меняется | Пример из нашей задачи |
|---|---|---|
| Data drift | распределение признаков `P(X)` | тариф подорожал, доля оптики выросла |
| Target drift | распределение таргета `P(y)` | доля оттока выросла с 21 % до 30 % |
| Concept drift | связь `P(y\|X)` | раньше дорогой тариф вёл к уходу, теперь нет |

Разница практическая: data drift виден сразу и без разметки.
Concept drift обнаруживается только когда пришли настоящие метки,
а это недели или месяцы задержки. Отсюда правило: мониторить вход
нужно потому, что это единственное, что доступно немедленно.

## Что объяснить обязательно

**Дрейф — не поломка.** Это нормальное свойство мира: цены меняются,
конкуренты запускают тарифы, приходит новая аудитория. Вопрос не в том,
чтобы предотвратить, а в том, чтобы заметить.

**Статистический дрейф ≠ проблема.** На выборке в миллион строк тест
покажет значимое различие в чём угодно. Нужен и размер эффекта,
и — главное — проверка, упало ли качество. Дрейф признака, который
модель почти не использует, безвреден.

**Версия Evidently.** API менялся между минорными релизами.
В курсе зафиксировано `evidently==0.4.40`. Скажите прямо: если студент
поставил другую версию и импорты не работают — сначала выровнять версию,
не переписывать код.

## Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `ImportError` из evidently | другая версия | `pip install evidently==0.4.40` |
| Дрейф не обнаружен | current слишком маленький | Минимум 1000 строк |
| Дрейф во всех признаках сразу | сравнивают train с train другого сида | Проверить, что current — именно `--drift` |
| Отчёт на 40 МБ | много колонок и строк | Ограничить выборку, это нормально |
| `KeyError` в `as_dict()` | структура ответа зависит от пресета | Печатать ключи, не гадать |

## Ключевая мысль

> Все предыдущие занятия защищали от ошибок в коде.
> Дрейф — это когда код правильный, а мир изменился.

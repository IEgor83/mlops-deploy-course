# Занятие 13. CD и релизы — план

**Цель:** образ собирается и публикуется автоматически по тегу;
студент понимает, что такое релиз и чем версия модели отличается от версии сервиса.

**Артефакт:** `.github/workflows/cd.yml`, образ в GHCR, релиз `v1.0.0`,
любой человек может запустить проект одной командой `docker run`.

## Тайминг

| Мин | Что |
|---|---|
| 0–10 | Проверка ДЗ: схема стенда, проверка фолбэка |
| 10–25 | Демо: путь от коммита до запущенного образа |
| 25–75 | Работа |
| 75–85 | Взаимная проверка: запускаем образ соседа |
| 85–90 | ДЗ |

## Демо (10–25 мин)

Вопрос для входа: «Ваш проект нужно показать заказчику на его ноутбуке.
Сколько шагов?» Обычно: клонировать, поставить Python, venv, зависимости,
dvc pull, обучить, запустить. Семь шагов и полчаса.

Целевой ответ — один шаг:

```bash
docker run -p 8000:8000 ghcr.io/<логин>/<репо>:1.0.0
```

Покажите его вживую на заранее опубликованном образе.

Затем разберите на доске цепочку:

```
git tag v1.0.0 → push → CD собирает образ → тесты образа → публикация в GHCR → релиз
```

Подчеркните: между тегом и опубликованным образом нет человека.
Человек принимает решение выпустить релиз, всё остальное делает автоматика.

## Что объяснить обязательно

**CI против CD.** CI отвечает «можно ли это мержить», CD — «выкатываем».
Разные триггеры: CI на PR, CD на тег.

**Семантическое версионирование** и главный вопрос занятия:
если переобучили модель, а код не менялся — это какая версия?

Разберите честно: это две разные оси. Версия сервиса (`v1.2.0`) — про код
и API. Версия модели (`churn-classifier v7`) — про качество предсказаний.
Их связывают, но не отождествляют: в ответе `/predict` вы уже возвращаете
`model_version` отдельно от версии сервиса.

**Проверка образа перед публикацией.** В CD обязательно должен быть шаг,
который поднимает собранный образ и дёргает `/health`. Публиковать
непроверенный образ — то же самое, что мержить без тестов.

**GHCR и права.** `permissions: packages: write` — без этого шаг падает
на публикации. `GITHUB_TOKEN` создаётся автоматически, отдельный
секрет заводить не нужно.

## Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `denied: permission_denied` | нет `permissions: packages: write` | Добавить в workflow |
| Workflow не запустился | тег запушен без `--tags` | `git push origin v1.0.0` |
| Образ опубликован, но `docker pull` даёт 404 | пакет приватный | Package settings → Change visibility |
| В образе нет модели | `models/` в `.dockerignore` | В CD обучать модель до сборки |
| Сборка в CD идёт 10 минут | нет кэша | `cache-from: type=gha` |

## Взаимная проверка (75–85)

Студенты обмениваются ссылками на свои образы и запускают чужой:

```bash
docker run -p 8000:8000 ghcr.io/<чужой-логин>/<репо>:1.0.0
curl -s localhost:8000/health
```

Не запустилось — обсуждаем почему. Это репетиция зачёта: там будет
то же самое, но с оценкой.

## Ключевая мысль

> Релиз — это не «залил на сервер». Релиз — это неизменяемый артефакт
> с версией, который можно запустить где угодно и откатить за минуту.

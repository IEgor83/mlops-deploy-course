# Занятие 10. Инференс-сервис на FastAPI — план

**Цель:** модель становится сервисом: принимает JSON по HTTP, валидирует вход,
возвращает предсказание с версией модели.

**Артефакт:** работающий сервис с `/health`, `/predict`, `/predict/batch`,
автодокументацией и тестами контракта.

> **Развилка курса.** К этому занятию у студента должен быть работающий
> пайплайн DVC. Если его нет — выдайте состояние `reference-project`
> с тегом `lesson-09` как точку старта (см. `docs/assessment.md`, «Долги»).

## Демо (10–25 мин)

Постановка: «Отдел маркетинга хочет узнавать риск оттока для клиента
в момент звонка в колл-центр. Как вы им это дадите?»

Разберите варианты из зала:
* «дам скрипт» — у них нет Python и данных в нужном формате;
* «сделаю CSV раз в сутки» — им нужен ответ сейчас, а не вчерашний;
* «дам ноутбук» — вопрос снимается сам.

Отсюда HTTP-сервис. Покажите эталон:

```bash
make serve
curl -s -X POST localhost:8000/predict -H 'Content-Type: application/json' -d @examples/request.json | jq
```

Затем откройте http://localhost:8000/docs и покликайте Try it out.
Скажите прямо: эта страница генерируется из типов Python, писать
документацию руками не нужно — и именно поэтому схемы важны.

Покажите отказ:

```bash
curl -s -X POST localhost:8000/predict -H 'Content-Type: application/json' \
  -d '{"tenure_months": -5}' | jq
```

422 с указанием, какое поле не прошло и почему.

## Что объяснить обязательно

**Модель грузится один раз, на старте.** Если грузить в обработчике,
p95 latency будет измеряться секундами. Показать через `lifespan`.

**Схема — граница системы.** Всё, что не прошло валидацию, не доходит до модели.
`Literal["month-to-month", "one_year", "two_year"]` ловит опечатку в категории
раньше, чем препроцессор молча заменит её на «неизвестно».

**Ограничение размера батча.** `max_length=1000` — не придирка: запрос
на миллион строк положит сервис по памяти. Отказ с понятным 422 лучше OOM.

**Версия модели в ответе.** Через месяц придёт вопрос «почему клиенту
дали такое предсказание». Без версии в ответе на него не ответить.

## Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Первый запрос идёт 3 секунды | модель грузится в обработчике | Перенести в `lifespan` |
| `KeyError: 'tenure_months'` | порядок колонок в DataFrame | Собирать через `df[feature_columns(params)]` |
| 500 вместо 422 | валидация делается вручную в коде | Отдать Pydantic, не проверять руками |
| `/docs` пустой | не указаны `response_model` | Добавить |
| Числа в ответе с 15 знаками | не округлено | `round(float(p), 6)` |

## Взаимное тестирование (75–85)

Студенты запускают сервисы и обмениваются адресами (`localhost` не подойдёт —
используйте IP в аудитории или сравнивайте попарно на одной машине).
Задача: сломать чужой сервис некорректным запросом. Всё, что вернуло 500
вместо 422, — материал для доработки.

## Ключевая мысль

> Валидация на границе — это не вежливость к клиенту.
> Это защита модели от данных, которых она не видела при обучении.

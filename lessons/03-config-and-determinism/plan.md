# Занятие 3. Конфигурация и детерминизм — план

**Цель:** два запуска обучения подряд дают идентичные метрики; ни одного
магического числа в коде.

**Артефакт:** `params.yaml` управляет всем; `reports/train_metrics.json`
побитово совпадает между прогонами.

> Это **сжимаемое** занятие. При потере пары из-за праздника проводится
> за 55 минут, остаток отдаётся на приём долгов по занятиям 1–2.

## Тайминг

| Мин | Что |
|---|---|
| 0–10 | Проверка ДЗ: чистый клон запускается |
| 10–20 | Демо: эксперимент с недетерминизмом |
| 20–70 | Работа |
| 70–85 | Приём долгов / разбор |
| 85–90 | ДЗ |

## Демо (10–20 мин)

Живой эксперимент на проекторе, три запуска подряд:

```bash
python -m src.train && python -m src.train && python -m src.train
```

Заранее уберите `random_state` из своей копии. Метрика скачет в третьем знаке.
Вопрос группе: «Я улучшил модель на 0.003. Улучшил или нет?»

Ответ, который должен прозвучать: без детерминизма отличить улучшение
от шума невозможно, а значит вся дальнейшая работа с экспериментами
(занятие 6) бессмысленна.

Второй заход: верните `random_state`, покажите совпадение до последнего знака.

## Источники недетерминизма — на доску

1. `train_test_split` без `random_state`
2. Инициализация модели (`RandomForestClassifier`, `GradientBoostingClassifier`)
3. Глобальный `np.random` — например, в генерации данных
4. Порядок строк после `groupby`/`merge` (в pandas стабилен, но не гарантирован API)
5. Многопоточность: `n_jobs=-1` в некоторых моделях меняет результат
6. Версии библиотек — самый коварный: код тот же, sklearn другой, числа другие
7. Хеш-сид Python (`PYTHONHASHSEED`) — влияет на порядок множеств

Пункт 6 — повод показать `requirements.txt` с зафиксированными границами
версий и объяснить, почему `scikit-learn` без версии в проде недопустим.

## Типовые ошибки

| Симптом | Причина |
|---|---|
| Метрика всё ещё скачет | `random_state` задан у сплита, но не у модели |
| «У меня совпадает, у соседа нет» | разные версии sklearn — идеальная иллюстрация п. 6 |
| Гиперпараметры в `params.yaml`, но в коде остались значения по умолчанию | конфиг читается, но не передаётся в конструктор |
| `KeyError` при чтении конфига | добавили секцию в `params.yaml`, но не в код (или наоборот) |

## Ключевая мысль

> Конфиг — это интерфейс эксперимента. Если для смены гиперпараметра нужно
> открыть .py-файл, у эксперимента нет интерфейса.

## Если успели раньше

Добавить в `train.py` запись в `models/model_meta.json` окружения прогона:
версия Python, версии numpy/pandas/sklearn, git sha, timestamp.
Это пригодится на занятии 6 и объяснит, зачем MLflow логирует то же самое.

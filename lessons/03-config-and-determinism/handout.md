## Шаг 2. Найти все источники случайности

Пройдите по своему коду и проверьте каждый пункт:

| Где | Что нужно |
|---|---|
| `train_test_split` | `random_state=params["seed"]` |
| Конструктор модели | `random_state=params["seed"]` |
| Генерация данных | `np.random.default_rng(seed)`, не `np.random.*` |
| Начало `main()` в `train.py` | `np.random.seed(params["seed"])` как страховка |

Про генератор: `np.random.default_rng(seed)` создаёт **изолированный**
генератор. Глобальный `np.random.seed()` влияет на весь процесс, и любая
библиотека может его сбить. Для новых данных всегда используйте `default_rng`.

## Шаг 3. Все числа — в конфиг

Прогрепайте свой код:

```bash
grep -rnE "=\s*[0-9]+\.?[0-9]*" src/ --include=*.py | grep -v "params\[" | grep -v "^src/config"
```

Каждое найденное число — кандидат в `params.yaml`. Исключения: индексы (`[:, 1]`),
очевидные константы (`1.0 - test_size`), номера версий.

Целевая структура конфига:

```yaml
seed: 42

data:
  n_samples: 20000
  raw_path: data/raw/churn.csv
  processed_dir: data/processed
  test_size: 0.2
  val_size: 0.1

features:
  numeric: [...]
  categorical: [...]
  binary: [...]

train:
  model: gradient_boosting
  logreg:
    C: 1.0
    max_iter: 1000
  random_forest:
    n_estimators: 300
    max_depth: 12
    min_samples_leaf: 5
  gradient_boosting:
    n_estimators: 200
    learning_rate: 0.05
    max_depth: 3

evaluate:
  threshold: 0.5
  min_roc_auc: 0.75
```

Обратите внимание на структуру `train`: гиперпараметры лежат в секции
с именем модели. Это позволяет писать так:

```python
name = params["train"]["model"]
cfg = params["train"].get(name, {})
model = RandomForestClassifier(random_state=seed, **cfg)
```

Добавление новой модели теперь = добавление секции в YAML + одна ветка `if`.

## Шаг 4. Порог качества

Добавьте в `params.yaml` ключ `evaluate.min_roc_auc: 0.75` и создайте
`src/evaluate.py`, который:

1. загружает `models/model.joblib`;
2. считает метрики на `data/processed/test.csv`;
3. пишет `reports/eval_metrics.json`;
4. **завершается с кодом 1**, если ROC-AUC ниже порога.

```python
if metrics["roc_auc"] < gate:
    log.error("ROC-AUC %.4f ниже порога %.4f", metrics["roc_auc"], gate)
    sys.exit(1)
```

Зачем ненулевой код возврата: на занятии 9 эту команду будет запускать CI.
Падение по метрике — такой же повод не пустить изменение в `main`,
как и падение теста.

Проверьте, что gate работает: временно поставьте `min_roc_auc: 0.99`,
запустите `make eval`, убедитесь, что упало, верните обратно.

**Почему тест отделён от валидации.** Валидацию вы смотрите постоянно,
подбирая параметры, — и незаметно подгоняете модель под неё. Тест
трогается один раз, скриптом, без вашего участия. Именно поэтому
`evaluate.py` — отдельная стадия, а не строчка в конце `train.py`.

## Шаг 5. Зафиксировать окружение

Проверьте `requirements.txt`. Версии без границ (`pandas`) недопустимы:
завтра выйдет новая мажорная версия и проект сломается на пустом месте.

```
pandas>=2.1,<3.0
scikit-learn>=1.4,<2.0
```

Запишите фактические версии, на которых получены ваши метрики:

```bash
pip freeze > requirements.lock.txt
```

Разница между двумя файлами: `requirements.txt` — то, с чем совместим проект;
`requirements.lock.txt` — то, на чём реально получен результат.

## Полезное

* `git rev-parse --short HEAD` — короткий хеш текущего коммита
* `PYTHONHASHSEED=0` — фиксирует хеширование строк в Python
* Правило: если значение появилось «из подбора» — ему место в конфиге,
  а не в коде

# Занятие 6. MLflow Tracking — план

**Цель:** каждый прогон обучения автоматически попадает в трекер;
сравнение экспериментов — в UI, а не в файле `EXPERIMENTS.md`.

**Артефакт:** MLflow поднят, ≥ 5 прогонов с параметрами, метриками
и артефактами; выбрана лучшая модель с обоснованием.

## Тайминг

| Мин | Что |
|---|---|
| 0–10 | Проверка ДЗ, обсуждение ответа «что хочу автоматизировать» |
| 10–25 | Демо: MLflow UI на 30 прогонах |
| 25–75 | Работа |
| 75–85 | Разбор + сравнение результатов группы |
| 85–90 | ДЗ |

## Демо (10–25 мин)

Начните с ДЗ занятия 3: попросите двух-трёх студентов зачитать
свои `EXPERIMENTS.md`. Обычно это таблица на 6 строк, уже неудобная,
местами с пропущенными столбцами. Спросите: «Что вы забыли записать?»
Правильные ответы: версия кода, версия данных, сколько обучалось,
как выглядела ROC-кривая.

Теперь откройте MLflow с заранее сделанными 30 прогонами:

```bash
mlflow server --host 0.0.0.0 --port 5000
```

Покажите:
* сортировку по метрике;
* сравнение двух прогонов бок о бок (Compare);
* параллельные координаты — как `learning_rate` влияет на ROC-AUC;
* артефакты прогона: сама модель, `params.yaml`, графики.

Ключевая фраза: «Это ваш `EXPERIMENTS.md`, только он заполняется сам
и ничего не забывает».

## Что объяснить обязательно

**Разделение DVC и MLflow.** Вопрос возникает у всех, ответьте до того,
как его зададут:

| | DVC | MLflow |
|---|---|---|
| Отвечает на вопрос | «как воспроизвести» | «что получилось» |
| Работает с | данными, стадиями, кэшем | прогонами, метриками, моделями |
| Живёт в | Git-репозитории | отдельном сервисе с БД |

Они не конкуренты. `dvc repro` запускает обучение, обучение логирует
прогон в MLflow.

**Что логировать всегда:** параметры, метрики, git sha, версию данных,
артефакт модели, конфиг. Правило: логируйте всё, чего вам не хватит
через три месяца, чтобы повторить прогон.

## Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `Connection refused` на 5000 | сервер не запущен | `mlflow server` в отдельном терминале |
| Прогоны валятся в `Default` | не задан `set_experiment` | Задать до `start_run` |
| Логируется, но пусто в UI | другой `tracking_uri` (файловый) | Проверить `mlflow.get_tracking_uri()` |
| `dvc repro` теперь требует MLflow | обучение жёстко зависит от трекера | Флаг `--no-mlflow` — обязателен для CI |
| В UI 200 прогонов за пару | логирование внутри цикла подбора | Обсудить вложенные прогоны (`nested=True`) |

## Ключевая мысль

> Эксперимент, который не залогирован, не проводился.

## Если успели раньше

`mlflow.sklearn.autolog()` — показать, обсудить, почему на реальном проекте
всё равно логируют руками (автолог не знает про версию данных и бизнес-метрики).

# Занятие 7. MLflow Model Registry — план

**Цель:** модель перестаёт быть файлом на диске и становится версионируемой
сущностью со стадиями; код загружает её по имени, а не по пути.

**Артефакт:** модель в реестре, версия в стадии `Production`,
`load_model()` работает по `models:/имя/Production`.

> Это **сжимаемое** занятие: при потере пары проводится за 55 минут,
> остаток — на приём долгов по блоку 1.

## Тайминг

| Мин | Что |
|---|---|
| 0–10 | Проверка ДЗ: 10+ прогонов в MLflow |
| 10–22 | Демо: сценарий отката |
| 22–70 | Работа |
| 70–85 | Приём долгов / разбор |
| 85–90 | ДЗ |

## Демо (10–22 мин)

Разыграйте сценарий, а не показывайте кнопки.

> Пятница, вечер. Выкатили новую модель. В понедельник маркетинг говорит:
> скидки уходят не тем людям. Ваши действия?

Соберите ответы. Обычно звучит «откатить». Дальше добивайте вопросами:
* Какую именно модель откатывать — как называется предыдущая?
* Где лежит её файл? Кто-нибудь его сохранил?
* На каких данных она обучалась?
* Сколько времени займёт откат — минуты или переобучение?

Теперь покажите Registry:

```
Models -> churn-classifier -> Version 4 (Production), Version 3 (Archived)
```

Откат = перевод версии 3 обратно в Production + `/reload` на сервисе.
Секунды вместо часов.

## Что объяснить обязательно

**Зачем реестр, если модель уже в артефактах прогона.** Прогон — это факт
из прошлого («вот что получилось 12 октября»). Реестр — это ответ на вопрос
«что сейчас в проде». Разные вопросы, разные сущности.

**Стадии как контракт между людьми.** `Staging` — «проверяется»,
`Production` — «работает на клиентах», `Archived` — «было, может понадобиться
для отката». Сервис знает только про `Production` и ничего не знает
про имена файлов.

**Про алиасы.** В MLflow 2.9+ стадии объявлены устаревшими в пользу
алиасов (`@champion`, `@challenger`). Скажите об этом честно: в курсе
используем стадии как более наглядные, но упомяните, что в новых проектах
пишут `models:/churn-classifier@champion`.

## Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| `RESOURCE_DOES_NOT_EXIST` при загрузке | нет версии в запрошенной стадии | Перевести версию в `Production` в UI |
| Загружается старая модель | закэширован объект в памяти процесса | Перезагружать явно, отсюда endpoint `/reload` |
| `registered_model_name` создаёт новую модель каждый прогон | опечатка в имени | Имя — из `params.yaml`, не хардкод |
| Сервис падает, когда MLflow недоступен | нет фолбэка | Обязательный запасной путь на локальный файл |

## Ключевая мысль

> Прод не должен знать имя файла модели. Он должен знать её роль.

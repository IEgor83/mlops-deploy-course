# Занятие 11. Контейнеризация — план

**Цель:** сервис едет вместе со своим окружением; образ собирается,
запускается и весит разумно.

**Артефакт:** `docker/Dockerfile` (multi-stage, non-root), `.dockerignore`,
образ < 500 МБ, `docker run` отвечает на `/health`.

> **Проверьте Docker в аудитории заранее.** Если он недоступен по политике —
> занятие переводится в режим демо преподавателя, студенты сдают Dockerfile
> без запуска (см. `docs/teacher-guide.md`, «Риски»).

## Демо (10–25 мин)

Соберите на проекторе наивный вариант — без `.dockerignore`, одностадийный,
с полным `requirements.txt`:

```dockerfile
FROM python:3.11
COPY . /app
WORKDIR /app
RUN pip install -r requirements.txt
CMD ["uvicorn", "src.service.app:app", "--host", "0.0.0.0"]
```

```bash
docker build -t naive .
```

Комментируйте вслух: «Sending build context to Docker daemon: 1.8GB» —
это `.dvc/cache`, `.venv` и данные уехали в контекст сборки.

Потом:

```bash
docker images naive        # ~2.5 ГБ
```

Спросите: «Что в этом образе лишнего для того, чтобы отдавать предсказания?»
Соберите список: mlflow, dvc, prefect, evidently, компилятор, тесты,
исходные данные, .git.

Дальше собирайте правильный вариант шаг за шагом и показывайте, как падает
размер. Финал: 2.5 ГБ → ~400 МБ.

## Что объяснить обязательно

**Контекст сборки ≠ образ.** Docker сначала отправляет демону всю папку.
`.dockerignore` работает именно на этом шаге — до всяких `COPY`.

**Multi-stage.** Первая стадия ставит зависимости (нужен компилятор),
вторая берёт только результат. Компилятор в финальный образ не едет.

**Порядок слоёв.** `COPY requirements.txt` и `RUN pip install` — до `COPY src/`.
Иначе правка одной строки кода инвалидирует кэш и переустанавливает
все зависимости. Покажите на секундомере: 4 минуты против 8 секунд.

**Non-root.** Процесс по умолчанию работает от root. Если сервис
скомпрометируют, внутри контейнера у злоумышленника будут полные права.
`USER appuser` — одна строка, снимающая целый класс проблем.

**Отдельный `requirements-service.txt`.** В образ инференса не нужны
mlflow, dvc, prefect, evidently. Это и размер, и поверхность атаки.

## Типовые ошибки

| Симптом | Причина | Решение |
|---|---|---|
| Сборка идёт 15 минут, контекст 2 ГБ | нет `.dockerignore` | Создать, пересобрать, показать разницу |
| `no such file: models/model.joblib` | модель в `.gitignore`/`.dockerignore` | Либо смонтировать томом, либо копировать явно |
| Любая правка кода = переустановка пакетов | неверный порядок слоёв | `COPY requirements` до `COPY src` |
| `Connection refused` снаружи | uvicorn слушает `127.0.0.1` | `--host 0.0.0.0` |
| Контейнер стартует и сразу выходит | ошибка в CMD | `docker logs <id>` |
| `Permission denied` после `USER` | файлы принадлежат root | Копировать до смены пользователя |

## Соревнование (75–85)

`docker images | grep churn` — у кого меньше. Победитель рассказывает,
за счёт чего. Обычно выигрывают те, кто вынес отдельный
`requirements-service.txt`.

## Ключевая мысль

> Контейнер отвечает на вопрос «в чём это запускать».
> Без него ответ звучит как «у меня Python 3.11 и вот такие пакеты, наверное».

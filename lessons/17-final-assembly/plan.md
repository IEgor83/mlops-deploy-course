# Занятие 17. Сборка проекта и репетиция защиты — план

**Цель:** проект приведён в состояние «готов к зачёту»; каждый студент
провёл демо целиком хотя бы раз.

**Артефакт:** релиз, README, ADR, закрытые долги, отрепетированная защита.

> **Сжимаемое занятие.** При потере пар сокращается до 45 минут:
> только прогон чек-листа и репетиция для тех, у кого проблемы.

## Тайминг

| Мин | Что |
|---|---|
| 0–15 | Прогон чек-листа всей группой одновременно |
| 15–30 | Разбор: у кого что упало |
| 30–65 | Работа: закрытие долгов, доводка README |
| 65–88 | Репетиция защиты в парах по 7 минут |
| 88–90 | Организация зачёта |

## Прогон чек-листа (0–15)

Все одновременно, на проекторе таймер. Команды диктуете вы,
студенты выполняют у себя:

```bash
git clone <свой-репозиторий> /tmp/check17 && cd /tmp/check17
dvc pull
docker compose -f docker/docker-compose.yml up -d
sleep 30
curl -s localhost:8000/health
curl -s -X POST localhost:8000/predict -H 'Content-Type: application/json' -d @examples/request.json
pytest -q
docker compose -f docker/docker-compose.yml down -v
```

Просите поднять руку на каждой упавшей команде. Считайте — это ваша
картина готовности группы к зачёту.

Типичная статистика: у трети падает `dvc pull` (забыли `dvc push`),
у четверти — `docker compose up` (пути от другой рабочей директории).
Обе проблемы означают незачёт на защите, поэтому чинятся сегодня.

## Про ADR (30–65)

Многие впервые слышат про Architecture Decision Record. Объясните
коротко и по делу: это ответ на вопрос «почему сделано так, а не иначе»,
записанный в момент принятия решения, пока причина ещё помнится.

Формат — четыре абзаца: контекст, решение, последствия, альтернативы.
Одна страница, не больше. Требуйте три ADR — этого достаточно,
чтобы навык закрепился.

Хорошие темы из их же проектов:
* почему модель грузится из Registry с фолбэком на локальный файл;
* почему в CI обучение идёт на 4000 строк, а не на полном датасете;
* почему выбран такой порог классификации;
* почему mlflow/dvc не попали в прод-образ.

## Репетиция (65–88)

Пары, по 7 минут на человека, строго по таймеру. Слушающий — «преподаватель»:
задаёт два вопроса и заполняет чек-лист из `docs/assessment.md`.

Требования к демо, объявите заранее:
* живой запуск, не слайды;
* начинать с чистого клона;
* уложиться в 7 минут.

Самая частая проблема репетиции — студент 4 минуты рассказывает
про задачу оттока и не успевает показать систему. Скажите прямо:
про задачу достаточно двух предложений, оценивается инженерия.

## Организация зачёта (88–90)

* порядок выступлений (жребий или список);
* что взять с собой: ноутбук, зарядка, переходник;
* что должно быть скачано заранее: docker-образы, зависимости
  (интернет в аудитории может лечь);
* дедлайн последнего коммита: за сутки до защиты.

Последний пункт важен: он отсекает «я доделаю утром».

## Чего не делать на этом занятии

Не вводите новых тем. Всё, что не собрано к 17-му занятию,
на зачёте не появится. Занятие целиком про доводку.
